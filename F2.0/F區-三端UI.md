# F 區「AI 大腦控制塔」— 三端 UI

寶鋪 showcase F 區的三個畫面：**桌面**、**牆面**、**iPad**。
這份文件說明三者各自長什麼樣、怎麼同步、以及共用的視覺語言在哪裡維護。

> 這是 UI 層的文件。NFC 協議的權威規格見 `vibenfc/SYNC-SPEC.md`，
> 展區內容規格見 `寶鋪 showcase/zones/F-AI大腦控制塔.md`。

---

## 一、三個畫面

觀眾把實體家電模型放上桌面的 NFC 感應區，三個畫面**同時**反應。

| 畫面 | Repo | Port | 角色 | 輸入 / 輸出 |
| --- | --- | --- | --- | --- |
| **桌面投影** | `F-table/web` | 5173 | 感應區本體 + 家電數據面板 | 收 WS、可送 session 控制 |
| **牆面投影** | `F-wall` | 5174 | 全屋走線與家電狀態的大畫面 | **只收不送**（`?sim` 是唯一例外）|
| **iPad** | `F-Ipad` | 5175 | 觀眾手上的知識圖譜 / 操作端 | 收 WS、送 session 控制 |
| WS server | `F-table/server` | 8787 | 權威資料源，接 ACR122U 讀卡機 | 廣播給三端 |

三端以**家電 id 路由**（`data.id`），不是以 slot 位置路由 —— 卡片放哪一個感應區都會亮對的家電。

| `hrv` | 新風機 | HRV-02 |
| `ac` | 冷氣 | AC-07 |
| `dehum` | 除濕機 | DH-01 |
| `purifier` | 空氣清淨機 | AP-06 |
| `sensor` | 12合一感測器 | SEN-09 |
| `light` | 燈 | LT-03 |
| `socket` | 智慧插座 | PG-04 |
| `curtain` | 窗簾 | CT-05 |
| `bathfan` | 浴室暖風機 | BF-08 |

## 二、同步模型

```
        ACR122U ×9
            │
   F-table/server (:8787)          ← 權威狀態在這裡
            │  broadcast
   ┌────────┼────────┐
桌面 5173  牆面 5174  iPad 5175
```

server 廣播四種卡片訊息 + 兩種 session 訊息：

| 訊息 | 意義 | 誰處理 |
| --- | --- | --- |
| `reader-connected` | 讀卡機上線 | 桌面、iPad（牆面略過）|
| `tag-present` | 卡片放上（帶 `slot_index` + `data`）| 三端 |
| `tag-remove` | 卡片拿走（**只帶 `slot_index`**）| 三端 |
| `reader-disconnected` | 讀卡機離線 | 三端 |
| `session-start` / `session-end` | 離開／回到歡迎頁 | 三端 |

⚠ `tag-remove` 不帶 id，所以每一端都必須自己記 `slot_index → id` 的對應，
才知道要熄滅哪一台。

⚠ session 控制由 iPad 或桌面送出，server 更新權威狀態後**轉發給所有人（含送出者）**。
前端是收到廣播才切畫面，不是送出當下就本地切 —— 這樣三端才會同時切。

## 三、共用的視覺語言

三個畫面的「淡藍發光線段 + 毛玻璃面板 + 走線彗星」是**同一套程式碼**，
不是各自調到看起來很像。

### 單一來源

| 內容 | 位置 |
| --- | --- |
| 顏色、毛玻璃、彗星參數 | `F-wall/src/config/fx.js` 的 `SHARED` |
| WebGL 發光層（shader / bloom / 彗星）| `F-wall/src/glow/` |
| 同步腳本 | `F-wall/sync-tokens.mjs` |

改完之後：

```bash
cd F-wall && node sync-tokens.mjs
```

會重新產生三端 CSS 的 `GLOW-TOKENS:BEGIN … END` 區塊、`glow/params.js`，
並把 `glow/` 與 `shared/` 複製到另外兩個 repo。

⚠ `glow/`、`shared/` 與 token 區塊在另外兩端是**複製品**，直接改會被下次同步蓋掉。
用複製而不是 import／submodule，是為了讓每個資料夾自帶完整程式碼 ——
現場單獨複製一個資料夾就能跑。

### 色票

| Token | 值 | 用途 |
| --- | --- | --- |
| `--glow` | `#A0D8FF` | 框架格線、家電框外圈、節點外圈 |
| `--glow-core` | `#DCEFFF` | 亮芯 |
| `--glow-beam` | `#7FE3FF` | 走線光束身部（彗星 body）|
| `--glow-deep` | `#1B4FA8` | 彗星尾端 |
| `--glow-head` | `#FFFFFF` | 彗星頭（超過 1.0 觸發 bloom）|
| 底色 | `#16181D` | 三端一致 |

⚠ **文字一律維持白色**，只有線 / 邊框 / 光暈染藍。展場觀眾偏年長，
藍字在投影上更難讀。

### 毛玻璃

`.panel-glass`（牆面）／ `.acard`、`.detail__card`（iPad）／ `.info-panel`（桌面）
共用同一組值：11% 白底、`blur(14px) saturate(1.2)`、淡藍高光邊、外緣光暈。

⚠ 毛玻璃**不可能**做進 WebGL —— `backdrop-filter` 是 CSS box 屬性，
SVG 與 WebGL 都沒有等價物。牆面自己也是用 `foreignObject` 包一個 div 來做。
三端的玻璃靠 token 統一，不是靠同一套繪圖。

## 四、分層原則（三端一致）

> **canvas 只負責「光」，要銳利的東西不要進來。**

```
  DOM / SVG   ← 文字、毛玻璃面板、實心白點、黑塊
  ─────────
  WebGL canvas ← 發光線、光暈、走線彗星（過 UnrealBloomPass）
  ─────────
  背景         ← 牆面：純色／iPad：俯視渲染圖
```

各端的實際 z-index：

- **牆面**：canvas 在底，SVG 疊在上面用純黑 `#000` 蓋掉往框內溢的 bloom
  （投影機的黑 = 不出光，實體展品才不會被打亮）
- **iPad**：`TOP.png`(0) → 發光層(1) → 連線 SVG(2) → 白點 / 卡片
- **桌面**：發光層(0) → 3D 區(1) → slot(2) → 連線 SVG(3)

⚠ 這個順序踩過坑：iPad 的背景原本疊在發光層之上，換成不透明的渲染圖之後
整層光被蓋掉。

## 五、牆面（5174）

**16:9 投影，`viewBox 1920×1080`。**

### 畫面組成

- **十一個純黑挖空框** —— 九台家電 + 中樞 + 電視預留區。
  這些是牆上**實體展品的預留位**，不是版面裝飾；座標改了現場就對不上。
- **背景框架** —— 大框（圓角矩形）+ 12 條正交格線，恆亮並緩慢呼吸（3 秒一輪）。
- **走線** —— 家電框 → 中樞框，感應時亮起並跑彗星。
- **狀態面板** —— active 時在家電框旁彈出的毛玻璃面板，含設備代碼、
  狀態列與 `MiniBars` 迷你長條圖。

### 狀態

| 狀態 | 家電框 | 走線 | 面板 |
| --- | --- | --- | --- |
| idle | 全暗（`blockIdle = 0`）| 不畫 | 無 |
| active | 亮起並呼吸（1.5 秒一輪）| 底光 + 彗星 | 淡入 |

⚠ 家電框與中樞框在沒感應時是**完全不發光**的 —— 那時它只是一塊黑，等卡片來才亮。
背景框架則一直亮著，兩者是不同的呼吸週期（3.0s / 1.5s，2:1 會週期性對齊）。

## 六、iPad（5175）

**橫向使用，觀眾手持。**

### 畫面組成

```
┌──────────────────────────────────────────┐
│ F  AI 大腦控制塔      已放置 n/9   已連線 │ ← StatusBar
├──────────────────────────────────────────┤
│ ┌──┐                              ┌──┐  │
│ │卡│      俯視渲染圖 TOP.png       │卡│  │
│ │片│   + 節點 + 光束 + AI 大腦環    │片│  │ ← GraphCanvas
│ │×5│                              │×4│  │
│ └──┘                              └──┘  │
└──────────────────────────────────────────┘
```

- **背景**：`public/TOP.png`（1920×1080 俯視渲染圖），四邊用 mask 羽化成黑邊。
- **節點**：九台家電在平面圖上的位置，active 時亮成近白色小圓點 + 淡藍發光外圈。
- **光束**：active 節點 → AI 大腦中樞，跑彗星，**終點停在中樞環外緣**不畫進環裡。
- **關聯邊**：兩端都 active 的家電之間連線（無彗星 —— 那是「關係」不是「資料流」）。
- **家電卡片**：左右各一排毛玻璃卡片，恆顯；active 時提亮並顯示即時數值。
- **完成浮層**：九台全部放上時淡入「全屋家電已串聯至 AI 大腦」。

### 座標約定

| | |
| --- | --- |
| 節點座標 | `src/data/appliances.js` 的 `pos`，0..1 相對 `.graph__plan` |
| 中樞座標 | `src/components/GraphCanvas.jsx` 的 `HUB`（%）|
| 尺寸（線粗 / 外圈 / 白點）| `src/lib/graphTuning.js` 的 `DEFAULTS` |

⚠ `pos.x` 必須落在 **0.15–0.85** 之間 —— 左右兩排卡片壓在平面圖上
（佔容器的 2–15% 與 85–98%），超出範圍的節點會被蓋住。

⚠ iPad 的線粗**刻意不跟 `SHARED` 走**（0.008 / 0.011，`SHARED` 是 0.013542）：
圖譜線要比牆面的格線細很多才好看。代價是改 `SHARED` 不會連動 iPad。

⚠ 白點只有 6px，但它同時是開啟詳細卡片的**點擊目標** ——
`.node--active::before` 另外給了一圈 44px 的透明觸控區。

## 七、桌面（5173）

**投影在桌面上，觀眾在這裡放卡片。**

### 畫面組成

```
┌────────────────────────────────────────────┐
│ 寶鋪 / …                            DARK   │ ← StudioHeader
├──────────────┬─────────────────────────────┤
│              │        ○ ○ ○ ○ ○            │
│  InfoPanel   │      ○           ○          │ ← 九個 NFC slot
│  （毛玻璃）   │   ○      ◎ 中樞     ○       │   排成 180° 扇形
│              │                             │
├──────────────┴─────────────────────────────┤
│              AI大腦控制塔                   │ ← frame-footer
└────────────────────────────────────────────┘
```

- **九個感應區**：沿一個扁橢圓的上半弧排開，單數位在外圈、雙數位內縮（`INSET_RATIO`），
  形成交錯的雙環扇形。中樞在弧的基線上，所以 NFC 01 ↔ 中樞 ↔ NFC 09 是一條水平線。
- **連線**：每個 slot ↔ 中樞，active 時發光並跑彗星。端點以 px 讓開中樞與圓環。
- **InfoPanel**：左側毛玻璃面板，顯示目前聚焦家電的
  今日用量 → 趨勢長條圖 → 本月累積 → 預測性維護排程。

### slot 三態

| 狀態 | 圓環 | 說明 |
| --- | --- | --- |
| 離線 | 極淡 hairline | 讀卡機沒連上 |
| connected | 邊框提亮 | 讀卡機在線、還沒放卡 |
| active | 淡藍高光環 + 微透明底 + 發光外圈 | 卡片在上面 |

⚠ 多台同時 active 時，InfoPanel 每 **8 秒**輪播一次（`ROTATE_MS`）；
新刷的卡會立刻奪焦並重新計時。停留較久是刻意的 —— 展場觀眾偏年長。

## 八、狀態與轉場

### Session

```
welcome ──(任一端送 session-start)──> live
   ^                                    │
   └────────(送 session-end)────────────┘
```

- 歡迎頁：純黑底 + 標題 + 指示文字，600ms 淡出（三端的時長綁在一起）。
- iPad 右下角有「重置」鈕給工作人員回歡迎頁。

### 動態原則

除了下列三項，**沒有其他循環動畫**：

1. 走線彗星（資料封包）
2. 底光呼吸（1.5 秒 / 牆面框架 3.0 秒）
3. 進出場淡入淡出（0.28s，`cubic-bezier(0.16,1,0.3,1)`）

⚠ **彗星不呼吸** —— 它是資料封包，跟著明暗會讀成訊號不穩。

## 九、開發工具與現場逃生開關

### 鍵盤模擬 NFC（沒有硬體時驗證三端同步）

```bash
cd F-table/server && npm run sim
```

三個畫面用**原本的網址**開啟，不用加參數。在**任一個視窗**（或跑 server 的終端機）按：

| 鍵 | 動作 |
| --- | --- |
| `1`–`9` | 放上／再按一次拿走該台 |
| `a` | 九台全放 |
| `0` | 全部拿走 |

⚠ 開關只有一個：server 要帶 `--sim`。沒帶時完全忽略，並在終端機提示一次。
現場的 server 不帶這個旗標。

### iPad 調參面板

按 `e` 開啟。可調發光線粗、節點外圈與中樞環半徑、白點大小，
並直接在平面圖上拖曳節點與中樞。調完按「匯出」貼回程式碼。

⚠ 覆寫值存在 localStorage，**不是設定檔**。面板關著但有覆寫值時左下角會提示。
展場的 iPad 沒有實體鍵盤，按鍵開啟不會誤觸。

### 牆面的網址參數

| 參數 | 作用 |
| --- | --- |
| `?all` | 強制九台全 active |
| `?fps` | 左下角顯示幀率 / 最長幀 / 掉幀數 |
| `?noglass` | 毛玻璃換成不透明底板（掉幀時的逃生開關）|
| `?nofx` | 完全不掛 WebGL 發光層（GPU 有問題時的逃生開關）|
| `?edit` | 面板版面編輯器 |
| `?glowdbg` | 保留繪圖緩衝，可用 `readPixels` 量真實輸出 |

### iPad

| 參數 | 作用 |
| --- | --- |
| `?ws=host` | 手動指定 WS server 位址（預設用 `location.hostname`）|

## 十、效能

三端都鎖 60fps（九台全滿實測）：

| | 中位幀 | p95 |
| --- | --- | --- |
| 牆面 | 16.7ms | 17.1ms |
| iPad | 16.7ms | 17.5ms |
| 桌面 | 16.7ms | 17.8ms |

⚠ WebGL 的內部緩衝**固定面積約 1.6 MP**，不跟著視窗尺寸跑。
一開始是固定寬度，容器變得又窄又高時緩衝會爆到 10 MP，而且 bloom 的
橫向／縱向模糊各自相對於解析度，非方形緩衝會把光暈拉成直立的橢圓。

## 十一、已知限制

- **毛玻璃無法進 WebGL**（見第三節），三端靠 token 統一。
- **iPad 直向**會把左右卡片擠在一起壓到平面圖 —— 展場橫放，不處理。
- **`--sim` 不能與真硬體同時用**：它會把九個 slot 標成虛擬讀卡機在線，
  真讀卡機插上來時會被跳過。
- **F-table 的 git 歷史有一顆 54.6MB 的 `.ply`**（3DGS 時期留下的，
  功能已移除但歷史清不掉）—— 不影響執行，clone 較慢。
