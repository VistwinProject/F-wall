# F-wall — 寶鋪 showcase F 區「AI 大腦控制塔」牆面投影

NFC 卡片放上桌面讀卡機 → 牆面對應的家電框亮成白高光、連線提亮、旁邊彈出狀態面板。
此專案只負責**牆面投影畫面**，資料權威源在桌面端，牆面**只收不送**。

完整規格見 `寶鋪 showcase/zones/F-AI大腦控制塔.md` 與 `vibenfc/SYNC-SPEC.md`。

---

## 技術棧

- **Vite 5** + **React 18** + **framer-motion 11**
- 純 **SVG** 場景（viewBox 1920×1080，16:9 投影面）
- 開發 / 預覽固定 port **5174**（`strictPort`，投影機 kiosk 指向此 URL，被佔用直接報錯不 fallback）

## 啟動

```bash
npm install
npm run dev        # http://localhost:5174
npm run build      # 產出 dist/
npm run preview    # 預覽 build 結果（同樣 5174）
```

### 除錯參數

- `?all` — 強制所有家電同時 active，用來驗證連線 / 狀態面板排版不打架。正式投影不帶此參數。
- `?fps` — 左下角顯示 FPS / 最長幀 / 掉幀數（見「現場效能驗證」）。
- `?noglass` — 面板換成不透明底板（毛玻璃的逃生開關）。
- `?nofx` — 關掉 NFC 感應特效：光暈 / 閃爍 / 能量光帶 / 彗星 / 面板邊緣高光（見下節）。
  走線本身仍然會亮起（那是行為，不是裝飾）。
- `?edit` — 面板版面編輯器（暫時性工具）。

## 資料流

```
桌面 Python WS server (ws://localhost:8787, 權威)
        │  只收不送
        ▼
useDeskState  ──►  activeIds (Set<id>)  ──►  WallScene
```

- 連線位址可用環境變數 `VITE_DESK_WS` 覆寫，預設 `ws://localhost:8787`。
- 斷線自動每 3 秒重連；斷線時清空 `activeIds`，避免卡在亮著的狀態。
- 協議四種訊息：`reader-connected` / `reader-disconnected` / `tag-present` / `tag-remove`。
- `tag-remove` 只給 `slot_index` 不給 `id`，故 hook 自記 `slot → id`（最後一次 `tag-present` 看到的 `data.id`），拿走卡片時才知道熄滅哪個家電。slot↔家電為動態綁定（方案 A）。

### 霓虹光暈

三層「**膨脹 → 模糊 → 衰減**」，參數在 `config/frame.js` 的 `GLOW`：

| 層 | dilate | stdDeviation | slope（衰減） | 峰值 |
| --- | --- | --- | --- | --- |
| `near` | 0.75 | 2 | 0.53 | ~29% |
| `mid` | 2.5 | 6 | 0.41 | ~17% |
| `halo` | 7 | 18 | 0.27 | ~9% |

最後把未模糊的 `SourceGraphic` 疊回最上面，亮芯保持銳利。可見半徑約 ±38 單位。

**⚠ 為什麼要先膨脹再衰減，而不是模糊細線再放大**

SVG 濾鏡的中間緩衝是 8-bit，**放大 alpha 不會產生新的階**，只會把既有的階攤得更開：

- 舊做法：模糊 1.5 寬的線 → 峰值 2.7% = 只有 **7/255 階**；×3.2 之後仍然只有
  `{0,3,6,10,13,16,19,22}` 這 8 個值，攤在 38px 半徑上 = 每階約 4.8px 的平台 →
  肉眼就是一圈圈色塊。
- 新做法：先 dilate 到 15.5 寬再模糊 → 峰值 33% = **85 階**（多 12 倍精度），
  再衰減到同樣的 9%。

實測（把畫面算繪到 canvas，橫切 x=1150 那條格線取樣）：

| | 舊（放大） | 新（膨脹+衰減） |
| --- | --- | --- |
| 平均色帶寬 | 3.8px | **2.36px** |
| 最寬色帶 | 7px | 5px |
| 外圈單調性 | 有回升（26→27→26） | **單調遞減** |

**剩下的極限**：8-bit 輸出在峰值 9%、半徑 38px 的條件下最多只有約 23 階，
所以理論下限就是約 1.7px 的色帶；最外圈（亮度只比底色高 1～4 階）那段梯度最平緩，
平台會到 4～5px。要再更平滑只能加 dithering 或改變衰減曲線，不是參數微調能解決的。

**另外兩個實作點：**

1. **`filterUnits` 一定要 `userSpaceOnUse`。** SVG 預設的 `objectBoundingBox` 對「完美水平／垂直的
   `<line>`」會塌成零寬高 → 光暈整個消失而且不報錯。12 條格線全是軸對齊直線，必中。
   （姊妹專案 `F-table` 的 `beam-bloom` 已踩過同一個雷。）
2. **`color-interpolation-filters="sRGB"`。** 預設 linearRGB 會讓光暈中段偏亮偏濁。

濾鏡區域用整個 viewBox。大框上下離畫布邊只有 47.5，可見半徑 38 還在裡面；
**`halo.sd` 調超過約 15 之後上下邊就會開始截斷。**

效能：一個濾鏡三次「膨脹+模糊」，但框架完全靜態（`LineFrame` 不吃 prop），
瀏覽器柵格化後會快取，**只付一次不是每幀**。`LineFrame` 另包了 `React.memo`。

### 資訊面板：毛玻璃

面板底板是**真的** backdrop-filter 毛玻璃，不是假的半透明疊層。

**做法**：`backdrop-filter` 是 CSS box 屬性，對 SVG 的 `<rect>` 完全無效
（SVG 1.1 規劃過的 `BackgroundImage` 濾鏡輸入沒有任何瀏覽器實作）。
所以底板改用 `<foreignObject>` 包一個 div，套 `.panel-glass`（`styles.css`）；
**文字仍然是 SVG `<text>`**，疊在玻璃上面，排版邏輯（`fitLabelSize` / 座標 / `tabular-nums`）完全沒動。

| | 值 |
| --- | --- |
| 底 | `rgba(255,255,255,0.11)` |
| 模糊 | `blur(14px) saturate(1.2)` |
| 邊 | `1px rgba(255,255,255,0.22)` + 上緣 `inset 0 1px 0 rgba(255,255,255,0.42)` |
| 陰影 | `0 10px 30px rgba(0,0,0,0.55)` |

**三個實作重點：**

1. **`foreignObject` 內 1 CSS px = 1 viewBox 單位**（實測：宣告 100px 的 div 在 svg 縮放
   0.3542 時實際寬 35.42px）。所以 blur / radius / shadow 都會跟著投影自動縮放，不用換算。
2. **`foreignObject` 會裁切內容**，所以它比面板大 `PAD=40`（內層再 padding 推回去），
   否則外陰影會被切掉。並設 `pointer-events: none`。
3. **文字要提亮**：底板從不透明變成半透明後，底色亮度由 ~10 升到 ~49，
   原本 `text3`(0.38) 的對比只剩 **3.25:1**（低於 AA）。新增 `textOnGlass`(0.55) 拉回 **5.10:1**，
   只用在面板內的設備代碼與資料列左標籤 —— 提亮文字，而不是把玻璃調濁。

**為什麼不用 HTML 疊在 SVG 上**：那需要 HTML 層與 SVG 算繪框完全重合，
會動到 `.wall-stage` 的結構，而那個結構決定九個黑塊落在牆上實體展品的哪裡。`foreignObject` 完全不碰它。

**退場**：面板層用 `AnimatePresence` 包起來，拿走卡片時淡出（實測 opacity 1 → 0.22 → 0.02 → 移除，約 300ms），
不再是瞬間消失。引線也移進了動畫群組，跟面板同步。

**進出場只做不透明度，不做位移**：會動的 `backdrop-filter` 元素是最貴的情況 ——
元素每移動一格，合成器就得把底下那塊背景重讀一次再模糊一次。九個面板同時進場
（全部刷卡、或斷線重連後 server 一次補回九張卡）正好是最壞情境。位置固定、只變 alpha
的話背景取樣可以重用。視覺上玻璃「就地浮現」也比滑進來更像玻璃。

### 現場效能驗證（`?fps` / `?noglass`）

`backdrop-filter` 的成本在開發機量不到 —— 隱藏的預覽視窗 `visibilityState` 是 `hidden`，
rAF 被節流到約 0.9fps。所以牆面自帶幾個現場用的 flag（與 `?all` 同一套慣例，正式投影不帶）：

| flag | 作用 |
| --- | --- |
| `?fps` | 左下角顯示 **FPS / 最長幀(ms) / 掉幀數**。看卡頓要看「最長幀」，不是平均 |
| `?noglass` | 面板換成不透明底板 —— 毛玻璃掉幀時的**逃生開關**，不用改碼不用重 build |
| `?nofx` | 關掉 NFC 感應特效（光暈 / 閃爍 / 光帶 / 彗星 / 面板邊緣高光）—— 走線本身仍會亮起 |

**上機第一件事**：開 `?all&fps`，那就是九個面板全開的最壞情況。
FPS < 50 或掉幀數 > 2 時浮層會轉紅。

降級順序：`FX.beam.on = false` → `?nofx` 關掉感應特效 → 減少 `config/fx.js` 的 `dots` →
拿掉 `FX.glow.outer` 那層 →
拿掉 `.panel-glass` 的 `saturate` → `blur` 14 調小 → 最後才 `?noglass` 回不透明底板。
若只有「九個同時進場」那一瞬間掉幀、穩定後正常，也可以改成錯開進場
（`AppliancePanel` 加 `transition.delay`），把尖峰攤開。

### 發光層：Three.js / WebGL（`webgl/` + `components/GlowCanvas.jsx`）

牆面所有的「光」都畫在一張 WebGL canvas 上，再過 `UnrealBloomPass`：
框架格線、家電框與核心框的外圈、走線光束、彗星。
SVG 疊在 canvas **之上**，只畫「擋光的」與「要銳利的」：十一個黑塊、白框、
電視預留區、毛玻璃面板、所有文字。

**為什麼換掉 SVG 濾鏡**：SVG 濾鏡的中間緩衝是 8-bit，細線經過大半徑模糊後峰值只剩十幾階，
色帶問題反覆調了三輪都只能壓不能解。bloom 在 half-float buffer 裡做，那一整類問題消失；
而且亮度可以超過 1.0，bright-pass 只讓真正的高光泛開 —— 光是「累積」出來的。

#### 四個踩過的坑（都花了不少時間，不要重犯）

1. **正交相機 y 向下 ⇒ 所有面都變背面。**
   `OrthographicCamera(0, 1920, 0, 1080, ...)` 的 `top < bottom`，投影矩陣的 y 是負的，
   三角形環繞方向整個翻過來。用預設的 `FrontSide` 會「draw call 有跑、但一個像素都不出現」。
   **所有材質都必須 `side: THREE.DoubleSide`。**

2. **雙重 sRGB 編碼 ⇒ 整張畫布霧成一片灰。**
   three 把場景畫進 EffectComposer 的中繼緩衝時就已經編成 sRGB（即使把緩衝標成
   `srgb-linear` 也一樣），`OutputPass` 會再編一次。實測背景 #16181D 的 22 變成 83。
   解法是 `renderer.outputColorSpace = LinearSRGBColorSpace`（改前 (83,86,95)、
   改後 (24,28,35)、目標 (22,24,29)）。**不要順手改回 `SRGBColorSpace`。**

3. **顏色要用 `col()` 建，不要 `new THREE.Color('#xxxxxx')`。**
   承上，整條管線等於不做色彩管理，而 `new THREE.Color()` 會把 sRGB 轉 linear，
   於是螢幕上比你打的色碼暗一大截，背景也跟 CSS 的 letterbox 邊界對不起來。
   `col()`（`webgl/stage.js`）指定 `LinearSRGBColorSpace` = 不要轉。

4. **內部緩衝固定 1920×1080，不跟著視窗跑。**
   讓緩衝跟著 CSS 尺寸走的話，在小視窗裡 1920 寬的版面被壓進 400px，每條線只剩 1px，
   bloom 的粗 mip 把它們攤成一層霧。固定之後不管在多大的視窗看都跟投影機上一樣，
   調參數才有意義。**副作用：在小預覽窗裡線條會細到看不清楚，那是縮放，不是壞掉。**

#### 對位

canvas 貼齊的是 **SVG 的內容框**，不是整個視窗（`xMidYMid meet` 在非 16:9 時會 letterbox）：
`s = min(W/1920, H/1080)`，尺寸 `1920s × 1080s`，置中。實測誤差 0.01px。
正交相機 1:1 對上 viewBox（`top=0 / bottom=1080` 讓 y 與 SVG 同向），
所以 `appliances.js` 的座標直接餵給 Three.js，不用任何換算。

#### 光束 shader

每條走線一片沿曲線鋪的三角帶（ribbon），`aT` 是沿線位置、`aSide` 是橫向。
`roundedRoute` 取樣 → `CatmullRomCurve3`（用它的 `getSpacedPoints()` 拿等弧長取樣）。
ribbon 蓋在**完整路徑**上（兩端伸進黑塊），所以彗星等待期自動隱形、抵達核心後被吃掉。

- 三階顏色：頭 `#FFFFFF` → 身 `#7FE3FF`（青）→ 尾 `#1B4FA8`（深藍）漸隱。
  實測沿線取樣：頭 (255,255,255) → (136,240,255) → (41,118,157) → (27,66,101) → 淡出。
- `uProgress` 一個 uniform 就是「射向中樞」的 draw-on。
- 頭部亮度推到 1.0 以上（`headBoost`）才會觸發 bloom。
- **底光（`beam.base`）讓整條線在感應期間持續亮著**，不是只有彗星掃過才看得到。
  亮芯 + 一點柔邊（`baseSoft`）—— 只有柔邊的話整條線會糊成一條霧、看不出是「線」。

#### 呼吸

感應期間，走線底光與「該台家電的框」一起做 2 秒一輪的緩慢亮暗（`FX.breathe`，
目前 0.72 ↔ 1.0）。**九台同相位**，讀起來是「一個系統在運轉」；想讓九台各呼吸各的，
把 `GlowCanvas` 裡算 `breathe` 的 time 加上 `phaseOf(i) * period` 就好。

⚠ 彗星本身不呼吸 —— 它是資料封包，跟著明暗會讀成訊號不穩。
⚠ 中樞框也不呼吸 —— 九條線的匯流點跟著明暗，會讓整面牆一起抖。

#### 框架的粗細與亮度統一

格線、大框、家電框、核心框全部同一個 ribbon 寬度（`FX.frame.width`），
且家電框 idle 的亮度倍率 `blockIdle = 1.0`＝與格線同亮 —— 背景框架是同一套東西，
不該因為是「框」還是「格線」而有兩種亮度。

⚠ 框架這一層用 **MAX 混色**（`MaxEquation`），不是加法。
八條垂直 × 四條水平 = 32 個交叉點，加法會讓每個交叉點亮兩倍，格線與大框、
格線與家電框重疊處也一樣，整片背景的亮度就不統一了。MAX 取較亮者，
重疊處與單獨一條線一樣亮，而且與繪製順序無關。實測交叉點／單線亮度比 = **0.998**。
（走線光束仍然是加法 —— 彗星掃過格線時本來就該更亮。）

#### 效能

九台都不 active 時 **rAF 會停掉**（實測 1.2 秒 0 幀），canvas 留著最後一幀＝靜態框架。

實測 `?all` 九台全亮：**60 fps、中位幀 16.7ms、最長幀 18.4ms、359 幀 0 幀超過 20ms**。
把面板的 `backdrop-filter` 拿掉再量沒有可量到的差別 —— 原本擔心「canvas 每幀都在動，
壓在上面的 12 塊毛玻璃要每幀重算背景」沒有成真。
⚠ WebGL 緩衝固定 1920×1080，所以 bloom 與場景的 GPU 成本與視窗大小無關，
這個數字對投影機是有代表性的；但畫面合成的部分在小視窗比較便宜，上機仍要再確認一次。

降級順序：`FX.dpr` 調到 0.75 → `bloom.strength` / `radius` 調小 → `sparks.max` 減少 →
`?noglass` → `?nofx`（完全不掛 canvas）。

#### 除錯參數

`?glowdbg` 會開 `preserveDrawingBuffer`，才能用 `readPixels` 量真實輸出 ——
在小預覽窗裡 1920 的畫布被縮到 400px 顯示，肉眼與截圖都看不出東西，只能用量的。
dev 模式下 `window.__glow` 掛著 stage / beams / 材質，主控台可以即時改參數再 `__glow.render()`。

### `?edit` 面板版面編輯器（暫時性工具）

調整面板位置／尺寸／數量用，**不是展場的一部分**。正式投影不帶這個參數時，
`WallScene` 完全不讀編輯器的值，走的還是 `ApplianceNode.panelBox()` 的自動版面。

http://localhost:5174/?edit

### 面板配置與內容

面板座標在 `config/panels.js`（由 `?edit` 編輯器調出來的絕對座標）。

- **`PANEL_LAYOUT`** —— 九個家電的狀態面板，刷到對應卡片才出現。
- **`CUSTOM_PANELS`** —— 三個附屬圖表面板，`of` 指定掛在哪一台家電旁，
  跟那台一起出現／消失：
  | id | 掛在 | 內容 | 尺寸 |
  | --- | --- | --- | --- |
  | `socket-chart` | 智慧插座 | 每日用電趨勢 | 90×140 |
  | `dehum-chart` | 除濕機 | 每日集水量 | 170×100 |
  | `ac-chart` | 冷氣 | 每日耗電 | 255×60 |

**內文排版會自己適應面板尺寸**（字級是原本的一半）：

- **行距固定 25**（對齊窗簾面板）。先前是「依高度平均分佈」，結果每塊面板行距都不同
  （實測 sensor 12、bathfan 13、其他 27~28），整面牆看起來不齊。
- 資料列**最多 5 列**，塞不下就少顯示幾列 —— 矮面板自然收到 2 列（感測器 115、暖風機 120）。
- 資料列並排放不下就自動改成「標籤在上、數值在下」兩行（`estWidth()` 估寬度判斷）。
- **列排完還有空間就補一張近七日趨勢小圖**（`status.trend`），兩段式：
  剩 ≥36 畫「標題 + 長條」，剩 ≥18 畫沒有標題的精簡版，再少就不畫。
  目前只有窗簾（剛好排滿）沒有小圖。
- `ChartPanel` 在高度 < 80 時（如 255×60 的冷氣圖表）自動改成「標題靠左、圖靠右」並排。

⚠ 圖表的 `data`、`status.trend` 與各家電第 3～5 列都是**假資料**，之後接 Welltek API 再換掉。

⚠ 面板改成絕對座標後，正式量牆校正黑塊座標時面板【不會】跟著跑，
要回 `config/panels.js` 重新對一次。

## 自動佈線（`routing.js`）

- 每條 trace 只走 **0° / 45° / 90°**（八方位）的線段。
- **與黑塊維持 `CLEAR = 30` 的淨空**：命中測試用「膨脹 30 之後的框」，所以避讓完自然就有
  30 的空隙。舊版是「貼著框判定 + 只推 8」，於是永遠只剩 8 —— 投影距離下看起來就是黏在框上。
- 障礙物包含**電視預留區**（規格明訂不准有連線穿過）。舊版完全沒檢查它，只是上排兩台剛好沒經過。
- `unGraze()` 處理「擦到自己的框」的兩種情況：線落在框外但貼著邊（沿邊擦過去），或落在框內但
  太靠近等一下要穿出去的那條邊（從框角切出去）。乾淨的走法只有兩種：夠深入框內（從邊的中段
  垂直穿出）或離框至少 30。
- 兩條主幹的避讓會互相推翻，所以來回收斂幾輪才定案。
- **資訊面板不算障礙物** —— 線可以直接穿過面板；面板會蓋在線前面（見下方「圖層順序」）。
- 佈線幾何（八方位、避讓、pad 落點）沿用，但畫出來的是 `roundedRoute()` —— 折點磨成圓弧
  （`FX.corner = 18`），詳見下方「NFC 感應特效」。`linePath()` / `chamferPath()` 仍匯出但已無元件在用。
- **規則就一句：從家電黑塊邊緣走到核心黑塊邊緣。** 畫出來的路徑兩端都切在黑塊邊界上，
  中間沒有任何藏起來的線段。
- 接點（pad）＝「核心中心 → 家電中心」這條射線打在**核心黑塊邊界**上的那一點，
  所以九個接點自然沿方位放射分布：左邊 417/534/642、右邊 417/534/642、下緣 792/960/1118。
  末段一律垂直插入該邊（`knee` 是 pad 沿邊法線往外推 46）。
  ⚠ 圓的概念（舊版的 `RING_R = 116`、`nearestOcti` 八方位斜插）全部拿掉了。
- `keepOffHub`：主幹經過核心旁邊時也要留 `CLEAR`，跟 `unGraze` 對家電框是同一個道理。
- **家電位置改了不用手動改線**，重新 build 時會自動重算。九台目前全部走自動佈線，
  已不需要 `appliances.js` 的手動 `route` 覆寫（舊版四筆是為了繞開鄰框，現在淨空邏輯直接處理掉了）。

### 中央 AI 核心（`Hub.jsx`）

**與九個家電同一個性質，所以畫法一模一樣**：純黑挖空 + 白框 + `RADIUS.sm` 圓角，
有任何一張卡片在感應時提亮一階並補上會呼吸的淡藍光暈。
`HUB = { x: 955, y: 550, w: 340, h: 340 }`，x/y 是**中心**（與 `ApplianceBlock` 同一個約定）。

⚠ 這塊**不放任何文字**。原本置中的「AI 大腦」四個字會直接把投影光打在實體展品上，
而 `fill="#000"` 的意義就是不出光。要標題的話得放在框外面。

⚠ 光暈（`HubGlow`）畫在黑塊**之前**，往框內溢的那半截才會被 `fill="#000"` 蓋掉。
它是九條線的匯流點，所以**不掛閃爍** —— 跟著閃會讓整面牆一起抖。

已確認與電視預留區有 25 單位間隙、與九個家電黑塊和十二塊面板都零重疊。

### 圖層順序

`WallScene` 刻意分批畫：**所有走線 → 感應特效 → 九個黑塊 → AI 核心 → 所有狀態面板**。
走線與感應特效都只有 active 的家電才會掛載。
若照家電逐一畫完自己的幾件事，排在後面的家電，走線會蓋在前面家電的面板文字上
（例如浴室暖風機的線橫切過窗簾的面板）。面板本身是毛玻璃（見下節），走線穿過時會被模糊成柔光帶。

⚠ 感應特效夾在「走線」與「黑塊」之間是**功能性的**，不是排版偏好：光暈會對稱地
往框內外兩邊擴散，往內那半截要被黑塊的 `fill="#000"` 蓋掉，才會只剩「黑塊外圍」在發光。
投影機的黑 = 不出光，光溢進黑塊 = 牆上的實體展品被打亮。

## 配色 / 設計 token

極簡黑灰白透明（樣本版），token 定義在 `src/config/theme.js`，三端共用同一組名稱與數值。

| 用途 | token | 值 |
| --- | --- | --- |
| 背景 | `bg` | `#000000` — 投影機的黑 = 不出光，牆上實體展品才不會被打亮。**這不是配色偏好，不要改成深灰。** |
| 面板分隔線 / 引線 | `line` | `rgba(255,255,255,0.10)`（走線已不再有 idle 態，沒卡片就不存在） |
| 家電框 idle / 面板外框 | `lineStrong` | `rgba(255,255,255,0.22)`，線寬 `LINE_W_IDLE` |
| active 高光 | `lineActive` | `rgba(255,255,255,0.85)`，線寬 `LINE_W` |
| 文字三階 | `text` / `text2` / `text3` | `0.95` / `0.62` / `0.38` |

家電框 idle 用 `lineStrong` 而走線用 `line`，是刻意分兩階：九個框是牆上實體展品的位置，
attract 狀態（還沒人刷卡）觀眾走近就該看得到；走線則要安靜。環境光會把投影的黑墊高，
`0.10` 那一階在現場幾乎看不見。

狀態色（`warn` / `err`）樣本階段一併走無彩，語意由文字與「圓點實心 vs 空心」承擔。
要開回琥珀 / 紅，改 `theme.js` 裡註解好的那兩行。

字體：Latin / 數字走系統字（`-apple-system` / `Segoe UI`）並開 `tabular-nums`；
CJK 用 Chiron Hei HK，fallback 到 `PingFang TC` / 微軟正黑體。
⚠ 字體是從 CDN 抓的，展場離線時會退到 fallback —— `portable/` 若要真的免連網，得把字體檔自帶進去。
